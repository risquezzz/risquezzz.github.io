Technical SEO Audit — imetal.com.ve

External review of crawling, indexing, structured data, performance and content architecture

Sitehttps://imetal.com.ve
Date11 November 2026
MethodExternal crawl plus analysis of HTML, headers and assets
Scope1 page, 35 images, 15 links
AuthorCristóbal Rísquez

1. Executive summary

The site is technically healthy at the basics and structurally empty where it matters.

HTTPS with HSTS, Brotli compression, one-year caching on images, correct 404 handling, a viewport tag, a self-referencing canonical and alt text on all 44 images: hygiene is solved. Response time is 98 ms and the HTML travels compressed from 104 KB to 22 KB.

The two problems that matter are not hygiene.

First, the structured data does not work. The application/ld+json block contains the JSON and then, immediately after it, a security JavaScript snippet pasted inside the same <script>. The result is a 2,043-character block that no parser can read. The LocalBusiness someone carefully wrote is not being interpreted by Google or by any AI engine.

Second, the site is a single page. Anchor navigation, zero internal URLs, a sitemap with one entry and 1,172 words for five service lines. No service pages, no case studies, no technical content.

That second point explains the GEO baseline result: IMETAL received zero mentions across 18 observations of conceptual queries. It is not an engine failure; there are no documents to retrieve.

Conclusion: fixing the Schema takes half an hour. Building the content architecture takes weeks. The first buys immediate credibility; the second is what changes visibility.

2. Scope and method

The review was performed from the outside, without access to Google Search Console or server logs.

What was measured.

  • HTTP response, headers and host redirection behaviour.
  • robots.txt and sitemap.xml.
  • HTML structure: title, meta description, headings, canonical, hreflang, JSON-LD.
  • Inventory of internal and external links.
  • Weight and format of every image asset declared on the page.
  • Image loading attributes: loading, srcset, dimensions.
  • Response caching for HTML and static assets.
  • Behaviour on a non-existent URL.

What could not be measured. Real indexation data (indexed pages, queries, impressions), server logs and field Core Web Vitals. PageSpeed Insights returned a 429 during the session, so performance is assessed through its structural causes rather than a lab score.

Why this is declared. An audit without Search Console sees half the problem. Stating it lets the reader know what is missing, and prevents indexation conclusions these data cannot support.

4. Findings

4.1. Critical — The JSON-LD cannot be parsed

Evidence. The application/ld+json block is 2,043 characters long. It begins with a well-formed LocalBusiness object and ends with JavaScript:

```

"sameAs": ["https://wa.me/582834006523"]

}

// ===== SECURITY =====

...

setInterval(check, 1000); })();

```

Why it happens. The template's security script was inserted inside the Schema tag instead of in its own <script>.

Impact. Google, Bing and generative engines cannot read the block. LocalBusiness, address, coordinates, opening hours and foundingDate are all lost: precisely the data that helps an entity be understood without ambiguity.

Fix. Move the JSON into its own <script type="application/ld+json"> and close the block before any JavaScript. Validate with the Rich Results Test and the Schema.org validator. A 30-minute change.

4.2. Critical — A single page has nothing to retrieve

Evidence. One HTML document, five anchors, 1,172 words, one URL in the sitemap.

Why it matters for GEO. Generative engines retrieve chunks. A one-page site offers a single chunk and competes against rivals publishing guides, service pages and case studies. When someone asks "how is a major overhaul of a centrifugal pump performed", there is no IMETAL document answering that question, so it cannot be cited.

Fix. Turn each section into its own URL: five service pages, one per line (machining, maintenance, rotating equipment rebuilding, infrastructure, logistics). Each with its own H1, technical content and service Schema.

4.3. High — 7.4 MB of unoptimised images

Evidence. 35 JPEG images, 7,377 KB in total. The heaviest is 607 KB, followed by 590, 575 and 510 KB. Zero loading="lazy" attributes, zero srcset, zero width/height, zero WebP or AVIF.

Impact. On mobile the carousel image competes for LCP. Without declared dimensions there is layout shift. Without srcset, a phone downloads the desktop asset.

Fix. Convert to WebP at quality 80, generate three sizes per image, declare width and height, add loading="lazy" to everything below the fold. Total weight can drop from 7.4 MB to under 1 MB with no visible loss.

4.4. High — www and non-www serve the same content

Evidence. https://imetal.com.ve/, https://www.imetal.com.ve/, http://imetal.com.ve/ and http://www.imetal.com.ve/ all return 200. There is no 301.

Impact. Two hosts with identical content. The canonical mitigates duplication but does not consolidate signals or stop links being shared to the wrong host.

Fix. Permanent 301 from www to the main domain (or the reverse, but one direction only) and from http to https.

4.5. Medium — Sitemap with a single URL and no lastmod

The sitemap declares only the homepage. That is consistent with the current state of the site, but it stops being useful as soon as service pages exist. Adding lastmod lets crawlers know what changed.

4.6. Medium — No English version

Evidence. The interface shows an ES | EN selector, but no /en/ path exists and there is no hreflang.

Impact. English queries are what generate most answers in ChatGPT, Gemini and Perplexity for an international buyer. A Spanish-only site is outside that conversation.

Fix. Publish the main pages in English with their own URLs and reciprocal hreflang. Not machine translation: written content.

4.7. Medium — Weak entity graph

Evidence. The Schema's sameAs points only to WhatsApp. No LinkedIn, no Google Business Profile, no sector directories.

Impact. Engines resolve entities by comparing independent sources. A single weak reference makes it hard to distinguish "IMETAL C.A." from similarly named companies, a real problem in this sector.

Fix. Add LinkedIn, Google Business Profile and the directories where the company already appears.

4.8. Low — The H1 loses spaces when parsed

Evidence. The extracted H1 text is SolucionesIndustrialesde Alto Nivel, with no spaces between the first words.

Cause. The H1 is built from several <span> elements with no whitespace between them. It looks right; to a parser it is a single word.

Fix. Add real spaces between the spans or use one text node. Low impact, one-minute fix.

5. What works and should not be touched

  • HTTPS with HSTS (max-age=31536000; includeSubDomains).
  • Brotli compression: HTML drops from 104 KB to 22 KB.
  • 98 ms TTFB in this measurement.
  • One-year caching on images; one day on HTML, appropriate.
  • Correct 404, with no soft redirect to the homepage.
  • X-Content-Type-Options: nosniff.
  • Correct viewport.
  • 44 images with alt text, none missing.
  • 71-character title and 113-character meta description: within range.
  • Correct self-referencing canonical.

The technical base is not the problem. It is worth saying so: whoever inherits this site should not rebuild what already works.

7. How this connects to the GEO baseline

The two studies explain each other.

The baseline measured what happens: 44.4% visibility, zero mentions across the six conceptual prompts, 24.4% verifiable citations.

This audit explains why: there are no documents to retrieve, and the Schema that should reinforce the entity is not parsed.

Together they define what to do: Schema and redirects first, then service pages, and only then measure again. The sequence matters: publishing content on a site with broken structured data leaves half the work without effect.

8. Limitations

  1. No Search Console or server logs. Real indexation, queries and bot crawling were not assessed.
  2. No field Core Web Vitals. PageSpeed Insights returned a 429 during the session; performance is judged by structural causes, not a score.
  3. Single measurement. Response times vary with network and time of day.
  4. No CMS access. Fixes are described at implementation level, not for a specific file.
  5. No backlink audit. Link profile and domain authority were not measured.

9. Conclusion

This site does not need a rebuild. It needs two half-hour fixes and one architectural decision that takes a month.

The Schema fix is the highest-return item in the whole project: half an hour to make the entity readable again. The content architecture is what changes the outcome, and it is what no competitor in the sector has done yet.
